How this page works

The dashboard is plain HTML, CSS and JavaScript. Live values come from three places: your browser (greeting, clock display), the web server’s time services, and the Java Servlet backend running on Apache Tomcat.

If the servlet chip in the header says offline, the page still works, but the servlet panels need the Tomcat backend. See the README for setup.

Session counter lives in the HttpSession. Each browser session has its own value, tied to a JSESSIONID cookie, and it restarts when the session expires or you press New session.

Application counter lives in the ServletContext. All visitors share one value, and it resets only when the web application restarts.

Laboratory 5

Network time: HTTP versus NTP

Current clock source: not synchronised

 

A browser cannot send NTP packets because NTP uses UDP port 123 and JavaScript has no UDP access. The portal therefore tries, in order: (1) the Java servlet, which performs a genuine NTP query on the server; (2) an HTTP time API; (3) the HTTP Date header of this site. The badge on the dashboard always names the source actually used.

Laboratory 4

W3C markup validation

Both pages use semantic HTML5 elements: header, nav, main, section, article, aside, footer, labelled form controls and a real data table.

  1. Open the official W3C Markup Validation Service.
  2. For the deployed site use Validate by URI. For local files use Validate by File Upload or Direct Input.
  3. Click Check and read the report. Fix every error, then validate again.
